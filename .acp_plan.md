## 1. Executive Summary

This specification defines the implementation approach for adding **UTP (uTorrent Transfer Protocol)** support to the Socketing-Communication-Chatroom application. The goal is to provide an alternative to TCP that offers lower latency, reduced resource consumption, and better performance in high-latency or congested network conditions while maintaining full backwards compatibility with existing TCP-based clients.

**Key Objectives:**
- Enable UTP as primary transport protocol
- Maintain TCP support for backwards compatibility
- Implement transparent protocol selection with automatic fallback
- Zero impact on existing message format and encryption
- Maintain chatroom functionality across protocol boundaries

## 2. Background & Context

### 2.1 Current Architecture
The application currently uses:
- **Transport Layer:** TCP (AF_INET, SOCK_STREAM)
- **Encryption:** RSA-1024 for message encryption
- **Client Interface:** Tkinter-based GUI
- **Architecture:** Star topology (centralized server, multiple clients)
- **Message Pattern:** Encrypted messages broadcasted to all except sender

### 2.2 UTP Protocol Overview
**UTP (uTorrent Transfer Protocol):**
- Lightweight, UDP-based congestion control protocol
- Designed for lower latency and reduced overhead vs TCP
- Connection-oriented semantic (similar to TCP)
- Multiplexing support
- Implemented as IETF RFC 6120
- Originally developed by BitTorrent Inc., now standardized

**Key Advantages:**
- Lower latency in congested networks
- Reduced CPU and memory consumption
- Better for mobile/IoT scenarios
- Non-blocking network congestion handling
- Natural UDP-based firewall traversal

**Key Challenges:**
- Requires UDP socket (firewall/NAT implications)
- Less ecosystem support than TCP
- No native Python stdlib; requires external libraries
- Debugging and performance monitoring complexity

### 2.3 Current Issue
Issue #1 requests UTP support to expand the application's capabilities and improve performance in diverse network conditions.

### 3.2 Protocol Abstraction Layer Design

**Core Abstraction Interface:**
```python
class TransportProtocol(ABC):
    """Abstract base for transport implementations"""
    
    @abstractmethod
    async def listen(self, host: str, port: int) -> None:
        """Start listening for connections"""
        pass
    
    @abstractmethod
    async def connect(self, host: str, port: int) -> Connection:
        """Establish outbound connection"""
        pass
    
    @abstractmethod
    async def accept(self) -> tuple[Connection, tuple[str, int]]:
        """Accept inbound connection"""
        pass

class Connection(ABC):
    """Abstract connection interface"""
    
    @abstractmethod
    async def send(self, data: bytes) -> int:
        """Send data, return bytes sent"""
        pass
    
    @abstractmethod
    async def recv(self, bufsize: int) -> bytes:
        """Receive data"""
        pass
    
    @abstractmethod
    async def close(self) -> None:
        """Close connection"""
        pass
```

### 3.3 Protocol Selection Strategy

**Server-Side Connection Negotiation:**
1. Client initiates with protocol preference (TCP or UTP)
2. Server responds with supported protocols list
3. Client selects best match (preferred if available)
4. Connection proceeds with selected protocol

**Client-Side Fallback Chain:**
- Primary: UTP (if configured)
- Fallback 1: TCP (always available)
- Fallback 2: Degraded mode (queue messages locally)

**Environment Variables for Configuration:**
```bash
CHATROOM_PRIMARY_PROTOCOL=utp    # utp or tcp
CHATROOM_FALLBACK_TIMEOUT=5      # seconds before fallback
CHATROOM_ENABLE_UTP=true         # explicitly enable/disable
```

## 4. Detailed Component Specification

### 4.1 UTP Transport Handler

**File:** `utp_handler.py`

**Responsibilities:**
- Wrap UTP library (libutp, async-utp, or custom implementation)
- Provide Connection interface implementation
- Handle UTP-specific connection lifecycle
- Manage UDP socket multiplexing
- Implement congestion control metrics

**Key Methods:**
```python
class UTPTransport(TransportProtocol):
    def __init__(self, host: str, port: int, config: dict):
        self.host = host
        self.port = port
        self.config = config  # MTU, timeout, congestion params
        self.socket = None
        self.connections = {}
    
    async def listen(self) -> None:
        """Bind UDP socket and start accepting UTP connections"""
    
    async def accept(self) -> Tuple[UTPConnection, Tuple[str, int]]:
        """Accept incoming UTP connection"""
    
    async def connect(self, host: str, port: int) -> UTPConnection:
        """Establish UTP connection to remote host"""
```

**Implementation Considerations:**
- Use `libutp` C extension if available (performance)
- Fall back to pure Python `async-utp` or `utp` package
- Handle UDP packet loss and retransmission
- Implement timeout and connection state tracking
- Manage connection ID multiplexing (UDP is connectionless)

### 4.3 Protocol Factory & Configuration

**File:** `protocol_factory.py`

**Responsibilities:**
- Create transport protocol instances based on configuration
- Handle protocol negotiation
- Manage fallback logic
- Provide protocol metrics and diagnostics

**Key Functions:**
```python
def create_transport(
    protocol: str = "auto",
    host: str = "0.0.0.0",
    port: int = 5000,
    config: dict = None
) -> TransportProtocol:
    """Factory function to create transport handlers"""
    
    if protocol == "utp":
        return UTPTransport(host, port, config or {})
    elif protocol == "tcp":
        return TCPTransport(host, port)
    elif protocol == "auto":
        # Try UTP, fall back to TCP
        return DualStackTransport([UTPTransport, TCPTransport])
```

### 4.4 Dual-Stack Connection Handler

**File:** `dual_stack_transport.py`

**Responsibilities:**
- Support simultaneous TCP and UTP listeners
- Route incoming connections to appropriate handler
- Manage protocol negotiation on connection
- Provide unified metrics across protocols

**Key Features:**
- Listen on same port for both TCP and UTP
- Client protocol preference negotiation
- Automatic fallback on protocol failure
- Connection pooling and load distribution

## 5. Integration Points

### 5.1 Server-Side Changes

**Current `server.py` architecture:**
```python
with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.bind((HOST, PORT))
    s.listen()
    while True:
        conn, addr = s.accept()
        # Handle client
```

**Refactored `server.py`:**
```python
from protocol_factory import create_transport

transport = create_transport(
    protocol=os.getenv("CHATROOM_PRIMARY_PROTOCOL", "auto"),
    host=HOST,
    port=PORT
)

async def main():
    await transport.listen()
    while True:
        conn, addr = await transport.accept()
        # Handle client (unchanged business logic)
        asyncio.create_task(handle_client(conn, addr))
```

**Changes Required:**
- Convert server to async/await
- Wrap socket operations with transport abstraction
- Add protocol metrics and logging
- No changes to `handle_client()` business logic
- No changes to encryption/message format

### 5.2 Client-Side Changes

**Current `client.py` connection:**

from protocol_factory import create_transport

## 18. Appendix: UTP Protocol Primer

### 18.1 Key Differences from TCP
- **Congestion Control:** Selective ack (SACK) instead of TCP's ACK every segment
- **Connection Model:** Similar to TCP but lighter weight
- **Ordering:** Maintains packet order like TCP
- **Reliability:** Guaranteed delivery with retransmission
- **Multiplexing:** Multiple connections over single UDP port

### 18.2 UTP Packet Structure
- Connection ID (32-bit)
- Timestamp (microseconds)
- Timestamp echo
- Sequence number
- Ack number
- Window size
- Type (SYN, DATA, FIN, RESET, etc.)

### 18.3 Connection States
- **IDLE** → SYN_SENT → CONNECTED → FIN_SENT → DESTROY
- State machine guarantees consistent behavior
- Timeout handling for reliability
